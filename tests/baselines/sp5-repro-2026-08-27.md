## What the reproduction shows

**The variable is not test order. It is the process ancestry of the pytest
run.** No prefix of other tests is required, and no other test participates:
the file *alone*, 14 node ids, reproduces the failure when it is launched the
way the ilk launcher launches things.

The sub-plan's stated premise — "something outside
`skills/ilk-watchdog/tests/` that runs before it in full-suite collection
order" — is **falsified by the run below**. There is no polluting test to
bisect for. The bisect over the collection-order prefix specified in step 0 was
not run: a prefix bisect cannot locate a condition that reproduces with an
empty prefix.

Minimal selection: `python3 -m pytest skills/ilk-watchdog/tests/test_scheduler_exit_reason.py -q --timeout=60 --timeout-method=signal` — run under `nohup python3 -c 'import os,sys; os.setsid(); os.execvp("/bin/bash", ["bash","-c",sys.argv[1]])' '<cmd>' >log 2>&1 </dev/null &`, the detach path at `skills/ilk-launcher/scripts/launch.sh:75`.

## Why `setsid` and not `nohup setsid`

`launch.sh:72` prefers `nohup setsid bash -c …`, but macOS ships no `setsid`
(`nohup: setsid: No such file or directory`, verified on this host), so this
platform always takes the `launch.sh:75` fallback. The reproduction uses the
fallback because that is what runs here.
