# 工单系统使用手册

> 给"人"看的操作手册（你 / 客户 / 团队成员）。
> 给 AI Agent 看的指引在 `SKILL.md`。

## 这是什么

一个用飞书多维表格做后端的工单系统。三方协作：

```
客户 ──飞书表单──> 工单池 ──"triage"──> AI ──> 你 ──> 代码 ──> staging
                                                                  │
                                                       客户验收 <──┘
```

- **客户**：通过飞书表单提工单（或者你帮他录入）
- **AI（我）**：自动 triage、排优先级、生成执行计划、关联 commit
- **你（开发/PM）**：在表格里看一眼 AI 的判断，必要时改一改优先级，然后告诉我"开搞"

## 一、提工单时填什么

打开飞书工单池里的 **`工单提交`** 表单视图（你建的）。**必填**字段加 ★。

### ★ 标题
一句话。例子：

| ✅ 好 | ❌ 不好 |
|---|---|
| 订单详情页点"取消"按钮报 500 | 不能取消 |
| 钱包充值后余额没刷新 | bug |
| 商品搜索结果按销量排序 | 想要个功能 |

### ★ 原文描述
**客户的原话**，别润色。AI 会自己理解。

> 例："我刚才下单后想取消，按了取消按钮就没反应了，过一会跳出来一个错误页面写着 500"

### ★ 在哪个页面
出问题/想加功能的那个页面 URL，**整段复制**。
- ✅ `https://v3-portal.thorder.com/orders/202604170012`
- ❌ `订单页`

如果是 Admin 后台，也直接贴 URL：
- ✅ `https://v3-admin.thorder.com/orders/list?status=10`

### ★ 录入端
- `Portal` — 客户端的问题
- `Admin` — 后台的问题
- `通用` — 不确定 / 跨端

### ★ 紧急度（**客户视角**的紧迫感）
- `紧急` — 影响所有人，需要今天修
- `高` — 影响很多用户，本周修
- `中` — 影响部分场景，本月修
- `低` — 偶发 / 体验问题

> 这是**客户感受**，不是"客观优先级"。AI 还会单独给一个 `AI 优先级建议`，两者可以不一样。
> 比如客户觉得"页脚字体小一点"是 `紧急`，AI 大概率会标 `P3`。

### 操作步骤（可选，建议填）
怎么走到出问题这一步：

> 1. 登录后到订单列表
> 2. 点"待付款"那条订单的"取消"按钮
> 3. 弹窗里点"确认取消"
> 4. 出现错误

### 期望看到（可选）
> 弹个"取消成功"的提示，订单消失或变成"已取消"

### 实际看到（可选）
> 浏览器跳到一个白屏，地址栏 URL 没变，控制台里 Network 看到 500

### 截图（强烈建议）
- 报 bug：截图必传，最好带控制台报错（F12 → Console / Network）
- 提需求：截图竞品 / 草图都可以
- 多张可以一起拖进去

## 二、跟 AI 说什么

直接在 Cursor 里跟我说话就行。下面是常用的"咒语"对照表。

### 1. 让我看新工单 / 自动 triage

```
看一下飞书工单池里的新工单
```
等价说法：
- `triage 一下新工单`
- `拉一下新提的工单帮我看看`
- `飞书有新工单吗？`

我会做的事：
- 把所有 `状态=新建` 的工单拉下来
- 每条判断 类型 / AI 优先级 / 涉及模块 / AI 理解
- 信息够 → 状态改成 `可执行`
- 信息不够 → 状态改成 `待澄清`，把缺什么写进 `缺失信息`，你回去问客户
- 给你一个一行总结的清单

### 2. 让我看某一个具体工单

```
看看 T-2026-0007 这个工单
```
或者：
```
T-2026-0007 是什么情况？
```
（带工单号我就知道去查）

### 3. 让我为某个工单生成执行计划

```
为 T-2026-0007 生成执行计划
```
等价：
- `T-2026-0007 写一个 plan`
- `这个工单怎么实现，给个方案`

我会：
- 读完工单全文（包括截图）
- 写一份 `docs/plans/YYYY-MM-DD-xxx.md`（/ilk-plan 风格的小步可验证计划）
- 在工单的 `关联 plan` 字段填上 plan 的 URL
- 状态改成 `计划中`

### 4. 让我开始干活

```
按 T-2026-0007 的 plan 开搞
```
我会：
- 状态改成 `实施中`
- 一步步执行 plan
- 提交时 commit message 自动带 `[ticket:T-2026-0007]`

### 5. 提交并跑测试

```
ship 一下
```
（已有的 `ship-and-test` skill 会被触发，做完后我会自动把 commit 关联回工单，状态推到 `待验证`）

### 6. 客户验收完，关单

```
T-2026-0007 客户验收通过了，关掉
```
我会：状态改成 `已发布` 或 `关闭`。

### 7. 日报 / 周报

```
今天的工单情况
```
或：
```
还有哪些工单待处理？
```
我会按状态分类列一遍：待澄清 / 可执行 / 实施中 / 待验证 各几条，P0/P1 单独点出来。

### 8. 自己手动改字段（不太常用）

如果你想直接让我改某个字段：

```
T-2026-0007 优先级改成 P0
```
```
T-2026-0007 这条标记为重复，跟 T-2026-0003 重复
```

## 三、状态都是什么意思

| 状态 | 谁推的 | 含义 |
|---|---|---|
| `新建` | 客户提交后自动 | 还没 triage |
| `待澄清` | AI | 信息不全，看 `缺失信息` 字段，回去问客户 |
| `可执行` | AI | triage 完，可以排进开发计划 |
| `计划中` | AI | plan 已写，未开工 |
| `实施中` | AI | 正在写代码 |
| `待验证` | AI（ship 完成后）| 已上 staging，等客户验收 |
| `已发布` | 你 / AI | 客户验收通过，已上线 |
| `关闭` | 你 | 不会做（决定不做、过期、撤回等）|
| `重复` | AI / 你 | 跟另一条工单重复 |
| `无效` | AI / 你 | 不是 bug / 不是问题 |

## 四、典型场景走一遍

### 场景 A：客户提了个 bug

1. 客户在飞书表单提交：标题"购物车数量改不了"，截图，紧急度=高
2. 你在 Cursor 里说：`看一下新工单`
3. 我返回：
   > T-2026-0042 [bug, P1] 购物车数量改不了
   > AI 理解：用户在购物车页点 + 号无反应，截图显示按钮 disabled
   > 涉及模块：portal/cart, api/cart
   > 状态：可执行
4. 你说：`T-2026-0042 写个 plan`
5. 我写好 plan，状态推到 `计划中`
6. 你说：`按这个 plan 开搞`
7. 我改代码、commit（带 `[ticket:T-2026-0042]`）、push
8. 你说：`ship 一下`
9. 测试通过，工单自动到 `待验证`
10. 你在飞书把 plan URL 发给客户验证
11. 客户 OK，你说：`T-2026-0042 关掉`

### 场景 B：客户描述太模糊

1. 客户提交：标题"很慢"，原文"网页很慢"，没截图，没 URL
2. 你说：`看一下新工单`
3. 我返回：
   > T-2026-0043 [待澄清]
   > 缺失信息：
   >  - 哪个页面慢（首页/搜索/订单/...）
   >  - 慢到什么程度（几秒？还是完全不响应？）
   >  - 什么设备/网络（手机/电脑，4G/Wi-Fi）
   >  - 截图或网络面板录制
4. 你把 `缺失信息` 复制粘贴回去问客户
5. 客户补充后，再说一次 `看一下新工单`（或客户改完工单状态会自动回到 `新建`）

### 场景 C：你想直接录入工单（不通过表单）

直接在飞书表格里加一行，把客户填的字段填上，状态填 `新建`，然后跟我说 `看一下新工单`。
效果跟走表单完全一样。

## 五、给客户的迷你说明（你可以转发）

> 提交工单时麻烦做到：
>
> 1. **标题写一句话**（不是"bug"或"建议"两个字）
> 2. **复制粘贴页面 URL**（不要写"订单页"）
> 3. **截图**（bug 必须，建议最好也有）
> 4. 报 bug 时，描述 **"我做了什么 → 期望发生什么 → 实际发生什么"**
>
> 信息越全，处理越快。

## 六、常见问题

**Q: 我不想让 AI 自动改优先级，怕改错。**
A: AI 改的是 `AI 优先级建议`，客户填的 `紧急度` 不会被覆盖。最终决定权在你 — 你可以直接在表格里改。

**Q: 截图能看吗？**
A: 能。让 AI triage 时如果有截图它会自动下载到本地 `tmp/screenshots/` 看。

**Q: 工单池可以多人协作吗？**
A: 可以。`处理人` 字段就是分配给谁的。多人同时填表都没问题。

**Q: 如果飞书 API 挂了？**
A: 工单池本身（飞书表格）不受影响，照常用。AI 这边的命令会报错，等飞书恢复就行。

**Q: 历史工单太多怎么办？**
A: 在飞书里建一个"已归档"视图（过滤 `状态 ∈ {已发布, 关闭, 无效, 重复}` 且 `最后更新 < 90 天前`），日常视图过滤掉这些就清爽了。
